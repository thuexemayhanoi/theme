# Nguyễn Tú grounded assistant V2 — context + lightweight memory

**Scope:** `thuexemayhanoi/theme` only, with `motoopen/chothuexemayhanoi` inspected READ ONLY. No source copied wholesale; no Motoopen contact data or unverified prices reused. This is a deterministic on-site information assistant **not a generative AI model**. No paid AI API and no open-source model used.

## What was learned from MotoAI V39

MotoAI V39 implements local NLP, term ranking (BM25), extractive sentences, user topic memory, source manifests and a phone dock-offset heuristic, with a 24h refresh and broad 80-page/site browser crawling budget. These ideas inspired the new version, but it **does not copy the V39 module or crawl from a visitor's device**. Motoopen's contact address and price statements are for a different entity and are not facts for Nguyễn Tú.

## New verified architecture

1. `inc/assist.php`: Normalize Vietnamese for intent and short vehicle names, recognize price/deposit/paperwork/delivery/directions/live availability/general queries. Only quote `inc/business.php` current price rows and business policy. Do not infer hourly prices, availability or promotional guarantees.
2. Prices, deposits, paperwork, electric and vehicle-overview questions use the **published, non-passworded WordPress FAQ post ID 484**, live location/delivery uses the **published contact page ID 372**. `get_permalink()` follows legitimate WordPress URL changes. Both IDs were confirmed on production read-only on 2026-10-19. Suppress draft/password/noindex sources.
3. Open-ended technical/content questions use one bounded WordPress `WP_Query` (max 12 examined, 3 links returned). Rank **title relevance first** with filtered Vietnamese terms, and reject results without adequate topic overlap. Updates are immediate with WordPress publishing; no new indexer, cron, full-site crawl or database table.
4. Optional context `{model,period}` is validated server-side against actual `nt_price_rows()`, not against arbitrary client prices. A follow-up `“Tháng thì sao?”` after `“Giá Honda Vision?”` can use the confirmed Vision month row; an unknown model never generates a price.
5. Client in `assets/js/assist.js` saves only confirmed vehicle name and rental period for up to **24 hours** (well under 512 characters); public related-link cards for generic discovery only, max **5 topics, 3 sources each, 8000 serialized characters, 6 hours**. No chat messages, passport numbers, names, emails, phone numbers or raw visitor questions are written to localStorage. Public source-card cache entries use one-way noncryptographic topic identifiers (not intended as security-grade anonymization) and are never submitted to another service. Cache is fallback-only when offline: primary answers always query current WordPress content. The clear button deletes both entries; failed/denied storage gracefully disables memory.
6. Source links are same-origin and inserted as safe text nodes. Status line uses `role=status` and `aria-busy`; answer sources labeled plainly; chat DOM retains one greeting + 12 messages for low memory usage. Keyboard focus returns to visible QuickCall launcher after the panel closes. Buttons and theme styling remain consistent; no third-party JS.
7. Refuse to present live inventory/special deals as verified. Hand off to Call/Zalo where current human confirmation is necessary.

## Performance and safety

- One bounded query *only for non-curated questions*; owner facts/FAQ links avoid an expensive broad text search for price/deposit.
- The visitor never downloads or indexes the WordPress sitemap or hundreds of posts. Frontend contact + assistant bundles have explicit raw/gzip budgets in `tools/qa/budgets.mjs`.
- User messages are sent to the website's own read-only WordPress REST route to answer them, not to a paid/third-party AI service. Do not confuse this with a promise that no HTTP request ever occurs.
- No changes to SEO metadata, canonical, schema, NAP, products, QuickCall links, Footer or WordPress posts.
- Opt-out: the visitor can press **Xóa ghi nhớ**; disabling browser storage also works, while server answers continue.
- Prior open PR #9 addresses related citation quality on an older base: V2 intentionally subsumes that fix; do not merge PR #9 into main afterwards without review. PR #49 (bounded BM25, combined price and deposit) was ported selectively by the Issue #62 work below; do not merge it as well.

## Update 2026-10-23 — six chips, contact and address, follow-ups (Issue #62)

**Approval.** The owner approved this fix inside Issue #62 as a scoped exception to the P0 Owner Lock: `inc/assist.php`, `assets/js/assist.js`, `assets/css/assist.css` and their tests. Quick Call (launcher, links, markup, styles), `color-mode.css`, `inc/enqueue.php`, `functions.php`, SEO output and WordPress content are untouched. The assistant is still a rule-based lookup of the owner's own data and public pages, not generative AI: no new API, model, plugin, cookie or stored chat text.

**Six quick questions.** The four old chips keep their labels and questions (`Bảng giá` → `Giá thuê Honda Wave`, `Đặt cọc` → `Tiền đặt cọc`, `Thủ tục` → `Thủ tục thuê xe`, `Xe điện` → `Xe máy điện`). Two are new: `Liên hệ` sends `Số điện thoại và Zalo liên hệ cửa hàng?` and `Địa chỉ` sends `Cửa hàng Nguyễn Tú ở đâu? Chỉ đường?`. They sit in a 3 × 2 grid of 44 px targets above the input; while the software keyboard is open they are hidden to leave room to type, and on screens lower than 520 px they become one scrolling row.

**Subjects, not one intent.** `nt_assist_topics()` reads the accent-free question and returns every subject it touches, in a fixed order: availability, contact, location, price, deposit, licence, documents, delivery, vehicles. A combined question (`giá Vision tháng và cọc`, `địa chỉ và số điện thoại`) therefore gets one answer with both parts. Contact words cover Vietnamese with and without marks, abbreviations (`sdt`, `sđt`, `lh`, `số đt`) and English (`contact`, `phone number`, `how can I contact you`); address words cover `địa chỉ`, `ở đâu`, `chỉ đường`, `mấy giờ mở cửa`, `where is your shop` and the like. Look-alikes stay out: `gợi ý` is not `gọi`, `gửi xe ở đâu` is parking, `cân bằng không` is not a licence question, and a `bao nhiêu` about people, weight, distance or fuel is not a price question. `Chi phí giao xe` and `giá giao xe` ask what delivery costs: they do not quote the remembered vehicle's rental price, which is added only when it is asked for in so many words (`giá thuê`, `bảng giá`, `theo tháng`) or a vehicle is named.

**Answers come from `inc/business.php` only.** Contact: the phone and Zalo number and the opening hours. Address: `nt_address()` and the hours. Price and deposit: the row of the owner's price table (`nt_price_rows()`) plus `nt_policy()`; the price note is added to every price answer. A cell that holds no amount (`Liên hệ`, `Báo giá riêng`, `Xác nhận theo mẫu xe`) is never turned into a number: the answer says the shop quotes it and the visitor gets the call and Zalo buttons. Stock, promotions and delivery area or fee are never promised.

**Licence and age.** The answer repeats only what the official consolidated text (55/VBHN-VPQH, read on 22 October 2026, `reports/legal-source-2026-10-22.md`) says in the articles it names, separates vehicle classes by design speed and engine size instead of by the word "50cc", and hands the vehicle-specific answer to the shop. For a 50cc question the owner-approved product page #669 is cited.

**Follow-ups.** The browser still keeps only `{model, period}`, validated on the server. A vehicle named in a price, deposit, stock or licence question replaces the remembered one and drops the old period (`Giá Vision tháng` → `Wave thì sao?` shows Wave, not Wave per month); naming the same vehicle again keeps the period (`Vision cọc bao nhiêu?` → `Giá bao nhiêu?` is still the Vision month); a period counts only in a price question (`hoàn cọc sau mấy ngày` is not a rental period); address, contact, paperwork and article questions leave the memory alone and never mention the remembered vehicle. `Tháng thì sao?` with no vehicle asks which one.

**Buttons.** The REST answer carries `actions` (new key; the old keys stay): `call` and `zalo` whenever the shop has to confirm or be reached (contact, stock, delivery, licence, quote-only figure, nothing found), `maps` for an address. Their URLs are `nt_tel_url()`, `nt_zalo_url()` and `nt_maps_url()` (the canonical business profile; the Quick Call share link is not reused). `assets/js/assist.js` accepts nothing else: `tel:` with digits only, `https://zalo.me/…`, a Google Maps or share host, no credentials in the URL, fixed Vietnamese labels, at most three buttons, links built from text nodes with `rel="noopener noreferrer"`. A hostile answer creates no script, no foreign link and no unsafe button.

**Reading suggestions.** An open question with no fact answer runs one bounded `WP_Query` (12 candidates at most) over published, non-passworded, indexable pages. Candidates must overlap the question on a specific word (a match on `điện` or `giá` alone does not count), the survivors are re-ranked with a mini BM25 that weights titles three times (ported from PR #49), and at most three are returned, introduced as `gợi ý đọc, không phải câu trả lời chính thức`. No score or ranking field leaves the server. Nothing relevant: the answer says so and offers call and Zalo.

**Tests and tools.** `tests/unit/AssistTest.php` (160 cases, pure PHP, ported PR #49 cases included), `tests/integration/NativeAssistTest.php` (16 new cases on real WordPress: markup, REST, sources, noindex/password/draft exclusion, reading suggestions), `tests/e2e/native-assist.spec.mjs` (21 new browser tests: layout at 360/390/768/1024/1440 px in light and dark, every chip, keyboard, hostile answer, error and timeout, short screen, software keyboard), `tests/node/assist-cases.test.mjs`. `tools/qa/assist-live.mjs` (workflow `Assistant live QA`, and the sandbox run as `candidate`) asks the same questions of a running site and measures the chat in Chromium; it is read-only. Chromium emulation is not native Safari.

**Rollback.** Revert the merge commit of the Issue #62 pull request. The browser memory format and the old REST keys are unchanged, so no stored value has to be cleaned; visitors who still have the old script cached keep working with the new answers (the extra `actions` key is ignored).
